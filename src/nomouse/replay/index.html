A menu opens, but keyboard focus stays behind it.

NoMouse walks a page with the keyboard only. Deterministic walkers judge what the DOM can settle, then Muse Spark 1.3 looks at the screenshots: did focus land inside what visibly opened, and did it come back on close?

  • 3 catches the walker misses, in both model runs, on builder pages labelled before any model call.
  • No false flag added over the walker on 20 clean controls. A plain Spark video prompt flags 16 and 15 of 20.
  • 0 of 10 correct triggers flagged on W3C's own reference widgets, in both runs. The walker flags 7.
